# 同一份模组，不同的实例：硬链接之外，服务器内容还需要什么边界？

客户端与服务端都可以复用同一个内容安装器，但复用代码并不意味着入口可以完全
相同。服务端多了两个问题：运行中的世界现在能不能修改？数据包究竟属于服务器，
还是属于某一个世界？

本文接续[内容登记表](06-content-links-and-registry.md)与
[服务端生命周期](03-server-lifecycle-and-worldsets.md)，只讨论组合后的额外约束。
依据是 Zig Core `5a4310d`；技术分析不代替未被记录的历史动机。作者确认的
[硬链接初衷](01-hardlink-storage.md)始终不变：保持版本隔离，同时减少相同文件的副本。

## 硬链接共享的是内容，不是管理权

同一份不可变模组可以由 CAS 保存，多个实例通过硬链接使用它。实例里的路径属于实例；磁盘上的字节可以共享。关闭某个模组，是把这个实例的链接重命名成 `.disabled`；删除模组，是移除这个实例的链接。两者都不应直接改写共享对象。

但 `.jmcl/content.json` 不是不可变模组。它记录这个实例选中了哪个项目、版本、文件，是否启用，以及是不是依赖。这些状态会变化，因此注册表采用原子替换，而不是把它作为共享内容分发。世界本身也属于可变状态，不能因为其中含有一些不可变数据包，就把整个世界塞进共享 CAS。

这里有两种不同的隔离：路径和注册表表达“这个实例拥有什么”；对象哈希表达“这些字节是什么”。把两者混为一谈，可能省下一点存储，却会失去实例的独立管理能力。

## 服务器的内容还受到时间边界约束

客户端文件管理回答的是“哪个路径可以改”；服务器还需要回答“现在能不能改”。运行中的服务器可能正在读取模组和世界数据。原实现让内容变更与服务器生命周期共用 `lockStopped`：先取得生命周期锁，确认服务器没有运行，再持有这个锁完成内容变更。

因此这不是一次 `is_running` 查询后马上释放锁。检查和变更之间如果允许另一次启动穿插，检查结果就失效了。Rust 门面复用同一个 guard，并让它覆盖元数据解析、下载、硬链接发布和注册表更新。

另一方面，列出内容并不要求服务器停止，也不获取这把锁。读取与变更不是同一种操作。重写不能为了统一代码，把本来允许的只读操作也挡住。

## 加载器限制不能变成禁止清理

安装模组需要 Fabric、NeoForge 或 Forge。原版 Vanilla 服务器无法加载这些模组，因而安装入口会先拒绝它。

但这不意味着“Vanilla 服务器上任何模组操作都违法”。列表、禁用、删除、接管已有文件仍有意义：目录中可能遗留旧文件，用户也可能需要清理。这些操作不能因为当前加载器为空而一概拒绝。

原实现把“需要模组加载器”作为**安装**这一行为的前置条件，而不是服务器目录的永久属性。版本切换另外保留内容引擎自身的兼容性检查。这种看起来不完全对称的接口，恰好表达了不同操作的真实职责。

## 数据包属于世界，不属于服务器根目录

服务器模组的注册表位于服务器根目录下的 `.jmcl/content.json`。数据包则属于 `server.properties` 中 `level-name` 指定的基础世界：

```text
server/
  server.json
  server.properties
  .jmcl/content.json       # 模组注册表
  mods/                   # 不可变模组的实例链接
  World/
    .jmcl/content.json    # 这个世界的数据包注册表
    datapacks/            # 不可变数据包的世界链接
```

这个位置选择让数据包注册状态和世界一同移动，而不是成为服务器根目录上的孤立记录。服务器世界管理虽然还认识 Nether/End 等耦合目录，但数据包门面不应该擅自把同一份数据包复制到每个维度目录。

世界尚未生成时，列表返回空，不创建世界；变更操作则按原行为创建基础世界目录。两者在可观察行为上再次不对称：观察不应产生目录，而安装可以在首次启动前完成准备。甚至找不到目标文件的删除操作，也可能已经创建了世界目录——这是现存可观察行为，重写不能把“更整洁”误当成兼容。

## 小门面不是“小兼容性问题”

Rust 实现没有再写一个服务器专用下载器，也没有换一种存储结构。它只负责组合几件已经存在的事情：服务器清单确定游戏版本和加载器；生命周期锁确定变更时机；基础世界确定数据包归属；内容引擎负责提供方解析与注册表；CAS 负责校验、共享和发布。

真正需要验证的是组合后的行为，而不仅是函数是否存在。我们用无真实网络的提供方夹具、无实际游戏的目录和注册表，逐项比较旧实现与新实现的事件、错误、退出码、文件名和注册表字节，并检查共享文件确实是同一个 inode。HTTP 元数据夹具替换过的旧版程序会单独标注，不把它称为真实网络兼容测试。

这也是重写最值得保留的经验：**共享字节不等于共享可变状态，复用引擎不等于省略边界，而兼容也不等于每个接口名字都能调用。**
