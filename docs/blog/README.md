# JMCL Core 技术文章：共享文件，不共享可变状态

Minecraft 的模组生态让许多实例长期并存：它们必须隔离版本，却常常拥有完全相同
的游戏、加载器和模组文件。项目作者确认，**在保持版本隔离的同时减少重复副本**，
正是选择硬链接式文件管理的原因。这不是 Rust 重写附带的一项优化，而是重写必须
延续的出发点。

本系列把原实现中值得保留的机制写成文章：问题是什么、实现如何取舍、代价在哪里，
以及新语言需要用什么证据继承它。文章不是变更日志，也不是替原作者补写未记录的
心理活动。除明确确认的动机外，方案比较均为基于代码的技术分析；目前没有材料
证明作者曾逐一考察并否决某些具体替代方案。

## 怎样阅读证据

- **历史事实**：原实现参照固定在 Zig
  [`5a4310d`](https://github.com/678mjoe/JMCLCore/commit/5a4310debbcee26b3d2391bab2339f79cd6ec52e)。
  第一篇另附初始存储、GC 和内容注册表的历史提交。代码能证明当时实现了什么，
  不能单独证明作者为什么否决一个未被记录的方案。
- **实现与测试**：文章中的 Rust 链接指向同分支的代码与测试。测试描述只对应列出的
  有限样例；测试文件存在，不代表它在所有平台上都运行过。使用合成元数据、模拟
  传输或修改过元数据获取的参照程序时，不把结果冒称为真实上游网络验证。
- **兼容范围**：以[逐方法证据清单](../../rust/compat/coverage.json)和
  [重写兼容性清单](../rewrite/compatibility.md)为准。方法数量、编译成功与单个平台
  的通过都不等于完整替换。历史里程碑报告只证明报告所固定的提交。
- **已知缺陷**：已获准对有源码和测试证据的旧缺陷在 Rust 中保留正确行为，并
  [逐项记录](../rewrite/original-core-defects.md)。这不是任意改变接口的许可；
  正常行为仍严格兼容，缺陷例外也不能被静默归一化为完全一致。

## 当前边界

开发位于长期 `rust-rewrite` 分支，**`main` 仍是 Zig，Rust 尚不能宣称完整替换**。
本系列是仓库内技术文章，不代表已发布到外部博客、切换前端或发布正式产品。

受管 Java 归档安装仍未完成，相关继续验证处于阻塞状态；本地或已经安装的 Java
路径不能证明自动获取流程已实现。已批准的[归档安全例外](../rewrite/archive-safety-decision.md)
只针对允许解压写入逃离暂存目录的链接，不是全面禁止符号链接，也不等于实现验收。
真实游戏、真实账号、长期服务端负载及各平台验收必须另有证据。
