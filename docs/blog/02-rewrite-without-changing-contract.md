# 换语言，不换契约：为什么重写需要两份程序同时运行

> 重写过程中的技术记录，不是发布公告。Zig 参照固定在
> `5a4310debbcee26b3d2391bab2339f79cd6ec52e`。下文区分可执行证据与设计分析，
> 不推测原作者当年未记录的决策过程。

“用 Rust 重写”看起来像是把结构体和函数翻译一遍，但对使用 Core 的前端来说，
语言不是接口。它看到的是一行 JSON、一个退出码、磁盘上一份现有实例，以及
删除一个实例之后其他实例是否仍然完整。因此，重写的第一道问题不是
“新程序能做什么”，而是“旧程序的使用者有没有被迫改变”。

## 一份契约有三个入口

第一层是 JSON Lines RPC。方法名相同不够：字段缺失与字段类型错误可能有不同
错误文本；成功事件有些带 `source`，另一些没有；同一进程读到坏请求之后
还要继续处理后面的请求。现在的[协议测试](../../rust/compat/check.py)直接比较
两个可执行文件的退出状态、stdout 与 stderr，不先把差异都整理成统一格式。
有序 JSON 构造让容易保持的字节顺序保持一致，但这不等于宣称 JSON 对象顺序
在所有使用者那里都有语义。

第二层是 CLI。CLI 不只是 RPC 的别名：usage、错误名、输出格式、退出码都是
脚本可能依赖的观察结果。[实例 CLI 对照测试](../../rust/tests/instance_cli_differential.rs)
把成功生命周期和错误参数都送给两个程序。测试“都失败了”并不能证明一个有效操作
移植成功，因此成功样例还必须独立断言其成功。

第三层是磁盘。重写不要求用户先运行一个“转换器”：Rust 写出的账户与实例，
Zig 要能直接读；反过来也一样。[账户对照脚本](../../rust/compat/accounts.py)
以及[实例接管测试](../../rust/tests/instance_differential.rs)使用同一个临时目录
交替执行两份程序。格式一致之外，还需要保持未知字段处理、错误文件行为和删除边界。

## 硬链接把“磁盘兼容”变成行为兼容

共享路径字符串不等于共享文件本体。硬链接式管理要求发布的是已经校验的不可变
对象；替换目录中的一个名字，不应偷偷改写其他实例正在引用的旧文件。
因此存储测试检查文件身份、链接数量、只读属性、替换后旧引用是否保留，
而不只是打开两个路径读到相同字节。

锁也一样。两个实现如果各自使用了一套“看起来相同”的锁文件协议，却不能真正
阻塞对方，就无法安全地接管共享存储。[跨语言存储测试](../../rust/tests/store_differential.rs)
让一端持有实际系统锁，检查另一端在锁持有期间与释放后的行为。
Unix 的对照表现为等待；Windows 固定参照的 GC 则在竞争时返回一个错误、
保留被锁对象，释放后重新执行才删除。后者证明了互斥，却不是相同的阻塞语义。
实验 CI 只精确记录这组结果，严格替换门槛仍然不通过。
跨文件系统时硬链接不可用；Linux 测试必须实际找到另一块文件系统，
否则显式失败，而不是跳过后宣称回退已经验证。

## “更严格”也可能破坏替换

安全边界不能靠一条全局规则代替阅读旧实现。配置根目录的祖先路径可能经过
系统提供的别名；实例描述文件也可能是只读别名。实际对照证据表明：
读取描述文件别名不应让删除操作转向外部文件。Rust 因而把“允许读取的别名”
与“锚定目录下的修改”分开实现，而不是因为重写就禁止一切符号链接。

另一类差异是 ZIP 校验接受范围。当前世界归档实现与 Zig 在 CRC 错误的接受上
仍有差异；这应记录为兼容差异，并分别审查路径、尺寸和内容边界，
不能仅凭“拒绝得更多”就宣布修复了安全漏洞。只读安装器 ZIP 元数据查找与
向文件系统解压也不是同一个安全问题。

## 固定旧版本，不代表复制每个偶然错误

固定版本的 RPC 缓冲区在丢弃超长行后，会同时清掉已经读入的下一条请求。
Rust 保留下一条请求。这个差异已被精确到三个输入/输出组合的测试记录；
临时实验模式只接受这三个已知结果，其他新差异仍失败。
严格替换检查仍不通过，是否修复参照实现并重新固定版本需要明确决策。

这就是差分测试的作用：它不是自动判定“谁对谁错”的法官，而是把设计决策
从模糊印象变成可复现事实。重写可以有改善，但改善不能伪装成无变化。

## 完成一个切片，不等于完成 Core

[逐方法证据清单](../../rust/compat/coverage.json)分别列出成功、错误、事件、磁盘、
平台与已知差异；列出了 106 个方法名不意味着这 106 个方法都已移植。
Linux 上通过也不能推导 Windows 上的句柄共享、目录重命名或真实进程行为通过。

现在的开发留在长期 `rust-rewrite` 分支，`main` 保持 Zig。
技术文章与测试一起记录已经取得的证据，也记录尚未取得的证据。
只有这样，未来切换语言才不会顺便要求用户更换工作方式。
